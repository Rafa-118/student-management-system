# EduManage

EduManage is a Flask student management system for Bangladesh. It provides protected administrator and student portals for managing students, courses, enrollments, attendance, results, and CSV reports. `showcase.html` is a separate animated portfolio page that the Flask app serves at `/showcase`.

## Technology

- Flask, Jinja, SQLAlchemy, Flask-Migrate, and Flask-WTF
- SQLite for local development
- PostgreSQL for production on Render
- Gunicorn for the Render production server

## Run locally on Windows

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
flask --app run:create_app db upgrade
flask --app run:create_app create-admin
python run.py
```

Open `http://127.0.0.1:5000/login` to sign in. Open `http://127.0.0.1:5000/showcase` for the public showcase page. The first administrator is created interactively—there is no default username or password.

## Test the project

```powershell
pytest
```

If your Windows sandbox prevents pytest from creating its default temporary directory, run:

```powershell
pytest --basetemp .pytest-tmp
```

## Database behavior

The local default database is SQLite at `instance/edumanage.db`. It is excluded from Git and should not be used for live Render data: a web service filesystem can be replaced during deploys and restarts. The included `render.yaml` provisions a Render PostgreSQL database and passes its connection string to `DATABASE_URL`; PostgreSQL data persists independently of the web service.

The committed `migrations/` directory contains the initial schema. Whenever models change, create and review a new migration locally before deployment:

```powershell
flask --app run:create_app db migrate -m "Describe the schema change"
flask --app run:create_app db upgrade
```

## Publish to GitHub

1. Create a new empty GitHub repository named `edumanage` without adding a README, `.gitignore`, or license.
2. In this project folder, run the following commands. Replace `YOUR-USERNAME` with your GitHub username:

```powershell
git init
git add .
git commit -m "Prepare EduManage for Render deployment"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/edumanage.git
git push -u origin main
```

3. Before pushing, run `git status`. It must **not** list `.env`, `instance/`, `*.db`, `.venv/`, or `__pycache__/`. The provided `.gitignore` excludes them.

## Deploy on Render

1. Sign in to [Render](https://render.com/) with the GitHub account that owns the repository.
2. In the Render Dashboard, choose **New** → **Blueprint** and select the `edumanage` repository.
3. Render finds `render.yaml` at the repository root. Review the proposed `edumanage` web service and `edumanage-db` PostgreSQL database, then click **Apply**.
4. Render installs dependencies with `pip install -r requirements.txt`, runs `flask --app run:create_app db upgrade` before each deploy, and starts the service with `gunicorn run:app`.
5. Wait for the deploy to show **Live**, then open the `https://…onrender.com` URL shown on the service page.
6. In Render’s web-service shell, create the first administrator once:

```bash
flask --app run:create_app create-admin
```

7. Sign in at `/login`, add a small test record, redeploy once, and confirm the record still exists. This confirms the application is using PostgreSQL rather than local SQLite.

`SECRET_KEY` is generated by Render and `DATABASE_URL` is linked from the Render database automatically. Do not paste either secret into source files or GitHub.

## Production settings

- Python version is pinned in `.python-version`.
- `render.yaml` uses the Singapore region and a free plan as a starting point. Confirm the available plan and pricing in your Render account before creating resources.
- A real production `SECRET_KEY` is required; the application refuses to start in production if it is missing.

## Scope

The current version intentionally does not include payments, SMS/WhatsApp, biometric/RFID hardware, profile-image uploads, public admissions, or teacher/parent portals.
